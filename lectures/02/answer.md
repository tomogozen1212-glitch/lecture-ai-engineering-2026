## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：
  - `num_train_epochs` を20から10に変更した。
  - モデル、学習データ、lora_r、lr、seedなどは同じ設定とした。
  - セッションを再起動し、変更後の条件で学習と評価を実行し直した。

- 結果（比較表や数字）：
  
| 項目 | 20エポック | 10エポック |
|---|---:|---:|
| 学習ステップ数 | 40 | 20 |
| 学習時間 | 245秒 | 119秒 |
| 最終Training Loss | 0.014127 | 0.100535 |
| 学習前format_rate | 9.52% | 9.52% |
| 学習後format_rate | 100% | 100% |
| 学習前content_rate | 0% | 0% |
| 学習後content_rate | 90.48% | 85.71% |
| 学習後の正解数 | 19/21問 | 18/21問 |

  - 学習回数を半分にすると、学習時間は245秒から119秒に短縮された。
  - 10エポックでも形式遵守率は100%に達した。
  - 内容正解率は20エポックの方が約4.76ポイント高かった。
  - 一方、10エポックでは正解したものの20エポックでは不正解となった質問も存在した。
  - 学習回数を増やすことが、すべての質問の正解率向上につながるわけではないとわかった。
  - 評価問題は21問と少ないため、今回の結果だけで一般的な性能差を断定することはできない。
 
- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く場面：
    - JSONなどの出力形式の統一や、決まった回答手順を習得させる場合。
    - 今回はわずか14件の学習データでも、形式遵守率が大幅に改善した。
  - 向かない場面：
    - 頻繁に更新される情報を正確に扱う場合。
    - 参照資料に書かれていない事実について、根拠の有無を厳密に判断する必要がある場合。
  - 今回の実験では、学習後も根拠のない断定が残った。このため、更新される知識にはRAGなどで外部情報を参照させ、根拠が不足する場合は人間による確認につなげる設計が必要だと考える。
